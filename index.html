職務要約

2014年に生命保険の基幹システム開発（COBOL / Java）でキャリアを開始し、要件定義から設計・実装・保守までウォーターフォールの全工程を経験しました。2018年にWeb系へ転向し、2019年9月に独立。2022年2月に合同会社広を設立し、現在は代表として複数のクライアントに参画しています。

Go / TypeScript（Next.js）/ AWSサーバーレスを主軸に、保険・予約・マーケットプレイス領域の業務システム開発に従事。現在は2案件でPMを務めています。いずれも実装メンバーとして参画した後、担当範囲が広がった結果としてPMを任されたもので、自分が設計・実装した領域をそのままマネジメント側で見ています。仕様が固まりきらないまま動き出した機能を引き取って要件から確定させる、遅延しているタスクのスケジュールを組み直す、といった役回りを担うことが多いです。

エンジニア歴12年4ヶ月（うちWeb系8年）、保険ドメインは通算8年以上です。

活かせる経験・スキル

  • 実装とマネジメントの兼務 — 設計・実装をしながら、進捗管理・アサイン調整・他チーム折衝まで担当
  • 一貫した開発推進 — 要件定義・仕様策定からアーキテクチャ設計、実装、リリース、運用まで
  • サーバーレスアーキテクチャ設計 — AWS CDK によるIaC、Lambda / API Gateway / SQS 構成の設計と運用
  • 認証・決済の方式設計 — パスキーを主軸としたMFA、信頼済みデバイス管理、決済ゲートウェイ連携、監査ログ設計
  • 外部システム連携 — 複数の外部予約経路と自社システム間のデータ同期設計
  • レガシー刷新 — PHP/CakePHP → Go/React、Vue/Nuxt → React/Next、Node(JS) → Node(TypeScript)
  • 保険ドメインの業務知識 — 生命保険基幹（手数料・企業会計）、ペット保険、保険金請求・査定

自己PR

実装から入って、任される範囲が広がってきたこと

現在PMを務めている2案件は、いずれも実装メンバーとして参画したものです。保険金請求・査定システムでは窓口精算と査定の両システムを自分で作り、その9ヶ月後にPMを兼務することになりました。ペット保険案件では、バックエンド、フロントエンド、PMと3年半かけて段階的に範囲が広がっています。仕様を理解した状態でマネジメントに回っているため、見積もりの妥当性や技術的な詰まりの判断が現場感を持ってできる点が強みです。

要件が固まっていない状態から動けること

仕様が曖昧なまま実装フェーズに入った機能を引き取り、関係者へのヒアリングで要件を確定させたうえで設計・実装まで通す、という進め方を繰り返してきました。法学部出身で非エンジニアとの対話に抵抗がないこと、生命保険基幹システム時代に顧客折衝と問合せ対応を担当していたことが土台になっています。

担当範囲を線引きせずに、遅延の原因に手を入れること

QAからの不具合報告が滞留していた際、自身の担当外でしたが放置すればリリース遅延に直結すると判断し、状況整理とアサイン変更を提案して解消に至りました。PMとして全体の納期を見る立場では、こうした「誰の担当でもない詰まり」を見つけて動かすことが最も効くと考えています。

レガシー刷新の経験を複数積んでいること

PHP/CakePHP → Go/React、Vue/Nuxt → React/Next、Node(JS) → Node(TS) と、稼働中サービスの技術刷新を複数の現場で経験しました。特に美容系予約システムでは、3年8ヶ月かけて大部分の移行を完了させています。動いているものを止めずに置き換える際の段階的な移行設計と、移行期間中の二重メンテナンスをどう畳むかについて、実践的な判断ができます。
